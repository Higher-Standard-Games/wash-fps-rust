# v1.0.0-beta13 papercuts

An overnight pass over the native client (wash-fps-rust) and the engine
(shagger), looking for performance, data flow, file size, security, privacy,
latency and bug papercuts. Each row is either **fixed** (merged to `main`) or
**proposed** (found, measured or reasoned about, but left for a decision
because it changes a format, a release step or player-visible behaviour).

PRs: shagger [#25](https://github.com/Higher-Standard-Games/shagger/pull/25),
wash-fps-rust (the PR that adds this file).

## Matrix

| # | Area | Finding | Severity | Status | Where |
| --- | --- | --- | --- | --- | --- |
| 1 | Security, privacy | The account key (the account's only credential) was written with the default umask, so other users on a shared machine could read it (0644). | High | Fixed: written 0600 with `write_atomic_private`; an existing key file is tightened to 0600 by `restrict_to_owner` before it is read. | shagger `core/atomic_file.rs`; wash-fps-rust `client/lobby_panel.rs`, `main.rs` |
| 2 | Security | "Save key file" built the file name from the player name. A name with `/`, `\` or `..` could write outside the chosen folder. | Medium | Fixed: `key_file_name` keeps only letters, digits, `_` and `-`; test `a_key_file_name_stays_in_its_folder`. | wash-fps-rust `client/profile_view.rs` |
| 3 | Security | HTTP fetches followed every redirect, including https to http, so a redirect could move a download (update index, levelshots, demos) off TLS. | Medium | Fixed: redirects that leave https are refused and chains stop after 10; test `a_redirect_is_followed`. | shagger `network/client/http_fetch.rs` |
| 4 | Security, performance | The update index, levelshots and demo downloads had no size cap, so a bad or hostile server could fill memory. | Medium | Fixed: `HttpFetch::start_at_most`; caps are 64 KiB for the index, 8 MiB per levelshot, 256 MiB per demo. | shagger `http_fetch.rs`; wash-fps-rust `update_check.rs`, `client/levelshots.rs`, `client/demo_download.rs` |
| 5 | Bug | A failed atomic write or rename left a `.part` file next to the target. | Low | Fixed: the part file is removed on failure; test `a_failed_write_leaves_no_part_file`. | shagger `core/atomic_file.rs` |

| 7 | Bug | `washoi bench --size WxH` was parsed but ignored, and the usage line did not list it; every bench ran at 1280x720. | Low | Fixed: `window::request_size`; checked with `--size 640x360`, which the report now prints. | 12 | Security | The self-update index (`latest.json`) and its SHA-256 come from the same server. Anyone who can change the release assets can change both, so the hash proves integrity in transit but not origin. | High | Proposed: sign the index with minisign or ed25519 in the release workflow, ship the public key in the binary, and refuse an unsigned or badly signed index. ## Checked and fine

- Nagle is already off on game sockets.
- Downloaded package names are validated before they touch the disk.
- No `unwrap` on data read from the network in the paths reviewed.
- The crash report carries no key, ticket or name.
- CPU frame cost is low. The baseline bench on `dm5` (1280x720, llvmpipe) takes
  about 3.6 ms of CPU per frame (feed 0.62, scene 1.0, prepare 0.38, encode
  0.76, submit 0.84 ms). The GPU, here a software one, dominates, so CPU-side
  optimisation has little to gain until it is measured on real hardware.
